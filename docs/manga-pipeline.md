# 異世界ニホン システム設計(NGT) — マンガ化パイプライン

版: v0.9
作成日: 2026-07-19

## この文書の位置づけ

本文書は、news-game-translator(Termux/NGT)を起点に、現実の政治ニュースを
「異世界ニホン」5コマ構成(起承転結4コマ+解説コマ)のマンガとして半自動生成し、
X投稿するまでのシステム全体設計を定める。世界観・キャラクター設定・縦読み版の
制作方針は docs/worldbook.md「漫画化の制作方針」節および manga/characters.md
を正とし、本文書はそれに加えてX投稿用の**5コマ構成**とその自動連携パイプラインを
規定する。

**5コマ構成は、docs/worldbook.mdが定める縦読み版(1話8〜12画面)とは別形式の
X投稿用短縮版である。** 縦読み版は将来展開として存置し、本文書のパイプラインが
対象とするのは5コマ構成のみとする。2形式は以下のように併記される:

| 形式 | 画面数 | 用途 | 制作方式 |
|---|---|---|---|
| 縦読み版 | 8〜12画面 | スマホでの縦読み連載(将来展開) | 手動、docs/worldbook.md準拠 |
| 5コマ構成 | 起承転結4コマ+解説コマ(計5コマ) | X投稿用短縮版 | 本文書のパイプラインで半自動生成 |

5コマ構成の内訳:

- **第1〜4コマ(起承転結)**: Manga News Packetの`panels`に対応し、コマごとに
  画像生成する(scripts/manga_schema.pyの`panels`は引き続き4要素固定)
- **第5コマ(解説コマ)**: `scribe_note`(書記官の解説)を表示するコマ。毎回
  画像生成はせず、書記官の正本画像(表情31種+書記局章、完成済み)から
  `scribe_panel`で指定した1枚を選択し、解説テキストを機械合成する
  (詳細は「マンガ生成方式」節参照。旧「事前生成した解説カットストック
  5〜10枚」という計画は、表情31種すべてが正本として完成したことで不要に
  なった、2026-07-24訂正)

完成画像の物理レイアウト(1080×1920px、5コマの座標・枠線6px・コマ間隔
19px等)は、comfyui-mobile-system側
`profiles/sdxl/isekai_nihon_manga/five_panel_template.json`(数値の正本)・
`five_panel_template.md`(人間向け解説)を正とする。本文書はPacketの
データ構造のみを規定し、座標等の物理仕様はcomfyui-mobile-system側へ
分離する(2026-07-23、正本テンプレート確定に伴い追記)。

## 目的

ニュースから「異世界ニホン」5コマ構成(起承転結4コマ+解説コマ)のマンガを
半自動で生成する。

最終的に人が行う作業は以下のみとする。

1. ニュース内容を確認
2. RunPodを起動
3. 「マンガ生成」を押す
4. 完成画像を確認
5. Xへ投稿
6. RunPodを停止

---

## システム全体構成

```
ChatGPT Work
    │
    ▼
ニュース収集
    │
    ▼
Termux (NGT)
    ・ニュース取得
    ・異世界ニホンへ変換
    ・validate
    ・Manga News Packet(JSON)生成
    ・ローカルHTTPサーバーで配信
    │
    ▼
app/isekai_inbox.html(NGT側 受信アプリ)
    ・ニュース受信箱
    ・内容確認
    │
    ▼
comfyui-mobile-system(異世界ニホンモード)
    ・RunPod接続
    ・マンガ生成(SDXL新規プロファイル、Phase 2以降)
    ・再生成
    ・保存
    ・X共有
    │
    ▼
RunPod + ComfyUI (SDXL)
    ・画像生成のみ担当
    │
    ▼
完成マンガ
    │
    ▼
X投稿
```

## 役割分担(確定)

- **ChatGPT Work**: ニュース収集のみ
- **Termux(NGT)**: 司令塔。ニュース解釈・5コマ構成(起承転結4コマ+解説コマ)・
  セリフ・プロンプト生成まで100%確定させ、Manga News Packetを出力する
- **RunPod + ComfyUI**: 確定済みPacketを画像化するだけ。解釈・脚色は一切させない

以下、各システムの役割の詳細を記す。

## 各システムの役割

### ChatGPT Work

現実世界のニュース収集のみを担当する。

### Termux(NGT)

ニュース処理の司令塔。

comfyui-mobile-systemはKick×Kickアイコン生成など他用途と共用の既存システムであり、

現状維持とし、異世界ニホン用にSDXLベースの新規プロファイルを**追加**する形で
対応する(詳細は後述「Phase 2方針」参照。Phase 2の作業でありPhase 1では実装しない)。

CMSから再利用するもの

- スマホ向けUI
- RunPod接続
- API管理

- 生成履歴
- 進捗表示

異世界ニホン用に新規追加するもの(Phase 2、CMS側)

- SDXL
- SDXL LoRA
- IP-Adapter
- キャラクター参照画像
- 4コママンガ向けComfyUI Workflow

既存のFlux.1用プロファイル・Workflowは変更・削除しない。異世界ニホン用の
SDXLワークフローは、既存プロファイルとは別の新規プロファイルとして追加する。

アプリ機能(異世界ニホンモード)

- ニュース受信(受信自体はNGT側の app/isekai_inbox.html が担当。下記「受信
  アプリの配置」参照)
- 内容確認
- RunPod接続
- マンガ生成
- コマ単位再生成
- 保存
- X共有

### RunPod + ComfyUI

RunPodは画像生成のみ担当する。

担当しないもの

- ニュース解釈
- 政治判断
- セリフ作成
- コマ構成

これらはすべてTermuxで確定する。

## Manga News Packet

Termuxからアプリへ送る構造化JSON。

含める内容

- 元記事URL
- 異世界ニホン版本文

  テキスト合成)
- 登場キャラクター
- 4コマ構成(起承転結、第1〜4コマとして画像生成)
- 各コマのセリフ
- 表情
- ポーズ
- 背景
- 事実保持の注意事項
- 画像生成用プロンプト
- キャラクター参照画像

RunPodは、この確定済み設計を画像化するだけとする(画像化するのは第1〜4コマの
みで、第5コマはRunPodでの生成対象ではない)。

具体的なスキーマ定義は scripts/manga_schema.py(Phase 1で実装)を正とする。

## マンガ生成方式

ページ全体をAIへ描かせない。第1〜4コマ(起承転結)と第5コマ(解説コマ)は
生成方式が異なる。

### 第1〜4コマ(起承転結、画像生成)

1. 1コマずつ生成
2. キャラクター参照画像で外見固定
3. 4枚完成後にコマ割り
4. 吹き出しと日本語は後処理
5. 失敗したコマのみ再生成

目的

- キャラクター崩壊防止
- セリフ崩壊防止
- 日本語文字化け防止
- コマ品質向上

### 第5コマ(解説コマ、確定仕様。2026-07-23改訂)

第5コマは毎回画像生成しない。書記官の正本画像(comfyui-mobile-system側で
登録・Release公開済み。表情31種+書記局章1種)から、Manga News Packetの
`scribe_panel`(`layout`・`expression`・`reference_image`・
`emblem_reference`)で指定された1枚を組版時に選択し、`scribe_note`の
テキストを機械合成する。`layout`は`scribe-left_note-right`固定(書記官を
左側、解説欄を右側へ配置)。

(旧記載: 「事前生成した書記官の解説カットストック5〜10枚から選択」と
していたが、書記官の表情セット31種+書記局章がすべて正本として完成済み
(2026-07-23)となったため、選択プールを全31種の標準表情タグへ更新した。
記事の内容・トーンに応じて`scribe_panel.expression`を選ぶ運用とする)

将来の拡張として、運用が安定した後に第5コマも毎回生成する方式(b昇格)へ
切り替え可能な設計とする(検証は後述「Phase 2調査項目」の「第5コマの毎回
生成化の検証」参照)。

## 通信(確定)

Termuxから、Termux上で起動するローカルHTTPサーバー1本を通じて、
Manga News Packet(JSON)とアプリのHTML/静的アセットを同一オリジンから配信する
(`file://` の直接開きはCORS制約により参照系リクエストが失敗するため不可)。
通信方式は本文書時点で確定済みであり、「実装時に選定」の対象ではない。

- サーバーはTermux上でPythonの標準ライブラリ(`http.server`)のみで実装し、
  追加の依存導入は行わない(Phase 1: scripts/serve_inbox.py)
- 同一端末上のブラウザ(app/isekai_inbox.html、および将来的にcomfyui-mobile-system
  の異世界ニホンモード)は、このローカルサーバーへHTTPでアクセスする
- GitHubやDiscordはニュース受信経路として使用しない
- Discordは通知用途(生成完了通知など)として利用可能

初期実装では同一端末内通信を前提とする。将来、端末を分ける必要が生じた場合の
通信方式(共有ストレージ・Android機能連携等)は、その時点で改めて選定する
(この将来課題のみが未確定であり、現行の同一端末内HTTPサーバー方式自体は確定済み)。

## 設計方針

- ChatGPT Workはニュース収集のみ担当する
- Termux(NGT)がニュース解釈・検証・マンガ設計を担当する
- RunPod + ComfyUIは画像生成専用とする
- GPUは必要時のみ起動し、コストを抑える
- 既存comfyui-mobile-systemのUI・RunPod接続・API管理などは活用する。既存の
  Flux系プロファイルは他用途と共用のため現状維持とし、異世界ニホン用は
  SDXLベースの新規プロファイル追加(Phase 2、上記「Phase 2方針」参照)で
  対応する。Flux基盤をSDXLへ全面移行することはしない

## 動作確認手順(Phase 1・ステップ3時点)

受信アプリ(画像生成なし版)の動作確認手順。RunPod接続・画像生成は
まだ実装されていない(「マンガ生成」ボタンは「準備中」のダミー表示)。

Termux側:

```bash
cd /root/news-game-translator
python3 scripts/serve_inbox.py
```

起動後、`受信アプリを起動しました: http://127.0.0.1:8787` と表示され、
`http://127.0.0.1:8787` で待ち受ける。

確認するPacketは `drafts/manga_packets/` 配下に置く(このディレクトリは
`.gitignore`対象。動作確認用に `data/state/manga_packet.example.json`
を `drafts/manga_packets/` へコピーして使ってよい)。

スマホブラウザ側(同一端末):

1. ブラウザで `http://127.0.0.1:8787` を開く
2. 「ニュース受信箱」に `drafts/manga_packets/` 配下のPacket一覧が
   日付・タイトル・状態(常に「生成待ち」)つきのカードで表示されることを
   確認する
3. カードをタップし、「内容確認」画面で元記事情報・異世界ニホン版本文・
   4コマ構成(起承転結、コマごとの場面・セリフ・表情タグ・背景)・
   第5コマ(書記官の解説)・注意事項が表示されることを確認する
4. 「マンガ生成」ボタンが「準備中」の非活性表示であり、押下しても
   RunPodへの接続が発生しないことを確認する(Phase 1・2ではRunPod接続は
   未実装)
5. 「← 一覧へ」で受信箱に戻れることを確認する
